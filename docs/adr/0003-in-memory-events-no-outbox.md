# ADR 0003 — Доменные события через SignalR, без очереди и transactional outbox

**Статус:** принято

## Контекст

Доменные события (создание лобби, ставка, завершение аукциона) нужно доставлять клиентам в реальном времени. Расчёт по итогам аукциона (передача предмета, списание с победителя, начисление продавцу) идёт синхронными межсервисными вызовами.

## Решение

Диспетчить доменные события **в памяти, после `SaveChanges`**, через SignalR-хаб Lobby.API (`IDomainEventDispatcher` → `IHubContext`). Без брокера сообщений и без transactional outbox.

## Последствия

**Плюсы:** минимум инфраструктуры; realtime без отдельного брокера.

**Минусы:** классический dual-write — событие рассылается отдельно от коммита в БД; при сбое диспетчера/краше между коммитом и отправкой событие теряется. Данные в БД при этом консистентны — теряется только realtime-уведомление.

## Почему outbox отложен

События — это UI-уведомления, не критичные для консистентности сообщения. Потеря = экран клиента временно устаревает; для баланса это дополнительно закрыто досинхронизацией на реконнекте (см. [0004](0004-signalr-balance-push.md)). Transactional outbox — узнаваемый паттерн, но при нашем характере событий его реальная польза низкая, а цена (таблица, фоновый диспетчер, идемпотентность) высокая. Внедрять — при появлении событий, которые нельзя терять (например, межсервисные денежные сообщения).
