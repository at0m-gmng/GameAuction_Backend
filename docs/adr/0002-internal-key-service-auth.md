# ADR 0002 — X-Internal-Key для межсервисной аутентификации

**Статус:** принято

## Контекст

Сервисы вызывают друг друга напрямую по HTTP (Identity → Catalog/Generation, Catalog → Generation/Lobby/Identity, Lobby → Catalog/Identity). Нужно отличать доверенный внутренний вызов от запроса игрока и не давать снаружи дёргать внутренние эндпоинты (выдача предмета, списание/начисление баланса).

## Решение

Общий секрет в заголовке `X-Internal-Key`, проверяется `IInternalCallerValidator` на внутренних эндпоинтах. Игроко-facing эндпоинты защищены JWT (см. `[Authorize]`). Один и тот же ключ используется и на входящую проверку, и на исходящие вызовы (заголовок на `HttpClient`).

## Последствия

**Плюсы:** просто, без дополнительной инфраструктуры (ни gateway, ни service mesh, ни mTLS); достаточно для нескольких сервисов.

**Минусы:** общий секрет, а не индивидуальная идентичность сервиса; нет ротации и отзыва; компрометация ключа открывает все внутренние эндпоинты. Для продакшена уровнем выше — API-gateway или mTLS. Приемлемо для демо-масштаба.
