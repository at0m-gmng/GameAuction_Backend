# ADR 0007 — Границы масштаба: что сознательно вне объёма

**Статус:** принято

## Контекст

Проект демонстрационный, портфельного масштаба: несколько игроков, по одному инстансу на сервис, Render free-tier. Ряд enterprise/scale-практик из ревью при таком масштабе не нужен и был бы оверинжинирингом. Чтобы это не читалось как «пропущено», фиксируем осознанные границы и путь развития для каждого пункта.

## Решение — сознательно НЕ внедряем сейчас (с путём развития)

- **Хранение токена:** JWT (60 мин) в `localStorage` на фронте. XSS-поверхность низкая (React экранирует, `dangerouslySetInnerHTML` нигде нет). → Прод: короткий access + refresh в `httpOnly`-cookie с ротацией.
- **Подпись JWT:** HS256 (симметричный общий секрет). → Прод: RS256 (приватный ключ у Identity, публичный у остальных — без общего секрета на валидацию).
- **Межсервисная аутентификация:** `X-Internal-Key` (см. [0002](0002-internal-key-service-auth.md)). → Прод: mTLS или OAuth2 client credentials. Вызовы в проде идут по HTTPS (публичные URL Render); `http://localhost` в appsettings — только локальная разработка.
- **Схема БД:** `EnsureCreated` + идемпотентные патчи (см. [0001](0001-ensurecreated-over-ef-migrations.md)). → Прод: EF Migrations (генерация через CI), что разблокирует blue-green/rolling с изменением схемы.
- **Наблюдаемость:** correlation ID + структурные логи (Serilog) есть. НЕ добавляем распределённый трейсинг (OpenTelemetry/Jaeger), метрики (Prometheus), алертинг.
- **Масштабирование:** один инстанс на сервис. НЕ добавляем SignalR backplane (Redis) для горизонтального масштаба и кеш (Redis) для витрины/профилей — при текущем масштабе БД-запросы дёшевы (нужные индексы есть).
- **Секреты:** локально — user-secrets, в проде — env-переменные Render (шифруются). НЕ добавляем выделенный Vault/Secrets Manager.
- **Деплой:** Render git-autodeploy (включён на всех сервисах) + GitHub Actions CI (сборка и тесты). НЕ добавляем канареечные/blue-green деплои и feature flags.
- **Health checks:** `/health` с проверкой БД, без разделения liveness/readiness — проект не на Kubernetes.

## Последствия

Проект остаётся сфокусированным на доменной логике и чистой архитектуре без инфраструктурного оверинжиниринга. Каждый отложенный пункт имеет явный путь развития при переходе к реальному масштабу — это осознанные решения, а не пробелы.
