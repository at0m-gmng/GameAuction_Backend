# ADR 0004 — Пуш баланса по SignalR вместо опроса

**Статус:** принято

## Контекст

Баланс игрока меняется вне его действий: по итогам аукциона победителю списывают, продавцу начисляют — это может произойти, когда игрок на любом экране или в открытом попапе. Первое решение — периодический опрос профиля (раз в N секунд) — нагружает систему и запрашивает баланс, даже когда он не менялся.

## Решение

Lobby.API после расчёта пушит событие `BalanceChanged` **адресно затронутому игроку** через аутентифицированный SignalR (`Clients.User`, идентичность берётся из claim `sub` через кастомный `IUserIdProvider`). Фронтенд по событию перезапрашивает профиль; дополнительно — разовая досинхронизация на `onreconnected`. Периодического опроса нет.

## Последствия

**Плюсы:** запрос баланса — только в момент реального изменения; мгновенно; без нагрузки опросом; адресная доставка (клиент не может подписаться на чужой канал — идентичность из подписанного JWT).

**Минусы:** зависит от живого соединения; пропущенный при обрыве пуш закрывается досинхронизацией на реконнекте. Требует аутентификации на хабе (токен в query-string, т.к. WebSocket не шлёт заголовок Authorization).
